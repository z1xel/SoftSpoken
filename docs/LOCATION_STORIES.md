# L8 — Stories geography integration

Stories resolves the shipped quest geography through the shared Octo Locations service. Three content namespaces are intentionally distinct: zones use spoken_classic/upstreamUiMap, turtleArea uses tortoise_snapshot/areaTable, and dungeon uses vanilla_instance_catalog/instanceMap. No field is interpreted as a native Octo ID simply because its numeric value matches. QuestSort remains non-geographical.

QuestCatalog:GetGeography(questID) exposes the canonical category identities and source/presentation context. QuestCatalog:GeographyLabel uses the same resolver as the tree. Geographic tree nodes and non-leaf QuestsTab rows carry locationID, and dungeon groups also carry contextLocationID for their entrance-zone filing. Canonically equivalent source area IDs group under the same reviewed legacy representative; duplicate category memberships are suppressed. A native custom instance remains an area category when it has no pinned upstream instance-map key. The existing source metadata supplies curated presentation filing (entrance zone, parent area, continent fallback), not a claim of physical containment. Existing city nesting is still a shared Compendium presentation projection. Registry kind controls dungeon/raid and PvP badges; the explicitly reviewed Sunnyglade PvP badge is retained because its registry kind is unknown.

Zone and instance labels use the registry with legacy labels only as compatibility fallback. QuestState:MapName no longer passes upstream IDs to native C_Map.GetMapInfo. QuestState:CurrentMap retains its old native numeric return contract; CurrentLocation exposes canonical live resolution. Existing geography fields, quest chains, class/race filtering, dialogue, speaker data, completion journal, discovery state, and audio contracts are unchanged. Unmapped source categories are retained without invented canonical IDs. Multi-zone quests retain membership in each category and count once in ancestor totals.

Tests: tests/stories_registry_octo.lua compares full-corpus category rosters with and without the registry, checks the scoped mappings and distinct instances, validates all geographical entries, retains sort-only and unknown history, and tests synthetic unmapped and repeated/multi-zone cases. Existing corpus and PvP checks remain. Live client verification belongs to L11. No Writings migration or SavedVariables migration is introduced.
