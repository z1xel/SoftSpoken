GOAL: The prototype should draw the SAME window while sample content and
behavior are supplied through a replaceable data provider. This is NOT a
production integration, not a new UI redesign, and not a replacement for

THE EXTERNAL PROVIDER INTERFACE (Lua 5.0 / Turtle WoW 1.12):
  provider:GetRows(mode, state)    -> flattened list entries
  provider:GetPage(mode, entry, state) -> {title, subtitle, text}
  provider:Visible(mode, row, text, state) -> boolean (optional)
  provider:CanSelect(mode, row, state) -> boolean (optional)
  provider:Counter(mode, row, state) -> string (optional)
  provider:IsSelected(mode, row, state) -> boolean (optional)
  provider:OnSelect(mode, row, state) (optional)
  provider:OnToggleGroup(mode, row, state) (optional)
  provider:OnSearch(mode, text, state) (optional)
  provider:OnModeChanged(mode, state) (optional)
  provider:GetFilters(mode, state) -> array of menu defs (optional)

  window:sszInstallProvider(provider)  -- runtime swap of data/callbacks
  window:sszSelectMode("books")         -- same existing native tab selection
  window:sszSelectMode("places")
  window.sszGetVisualControls()        -- returns owned UI controls for porting

HOW TO EXERCISE A PRODUCTION-LIKE CALLBACK CONTRACT (DEVELOPMENT ONLY):
  local bridge=SSZPortraitCompendiumAdapter.New({
     places={build=function() return rows end,
             isSelected=IsSelected, onClick=Select, onSearch=OnSearch,
             only="Discovered Only", onlyGet=OnlyGet, onlySet=OnlySet,
             checks=checks, page=function(row) return MakePageEntry(row) end},
     books={build=BookRows, isSelected=BookSelected,
            onClick=BookSelect, onSearch=BookSearch,
            checks=bookChecks, page=MakeBookEntry},
  })
  SSZPortraitDemoWindow:sszInstallProvider(bridge)

NOTE: Above is an interface example, not copy/paste integration code. In real
SoftSpoken, Books registers under 'readables', whereas prototype mode is
'books'; map these keys during the actual production integration.
